# 打纸杯小玩法 · 开发计划 v1（2026-10-15 起，90 天）

> 北极星：90 天内上线 + 签约 3 家公会 + 首批 ≥20 个直播间挂载；同时保住"一年 20 万"的主线（AI 交付）不受影响。
> 原则：游戏是期权，不是主食。所有里程碑都有 kill line，到点不达标就降级，不恋战。

## 0. 产品定义（冻结，任何迭代不得突破）

| 项 | 规则 | 理由 |
|---|---|---|
| 资金流 | **单向**：礼物只进不出，无回兑、无兑换、无下分、无返水、无站外交易 | 涉赌三要素红线（最高检口径） |
| 玩法结构 | **无对抗、无阵营、无输赢**：全房间共同打杯，只计"总命中/最高连击/高光时刻" | 打赏新规负面清单：诱导 PK、虚假榜单、门槛式打赏 |
| 礼物角色 | 礼物 = **加量器**（多发几发/特殊弹效），弹幕 = 免费参与（带冷却） | 礼物不是入场券、不是武器 |
| 话术 | 用"命中 / 没倒 / 倒了 / 连击"，禁用：赢、输、押、赔率、包中、下分、返点 | 禁用词库写进代码 + 审核材料 |
| 视觉 | 卡通手绘风；**无仿真枪、无血腥、无写实枪声**（音效用"duang/boing/pong"卡通音） | 抖音《直播行为规范》一级违规项 |
| 声音/出镜 | 主播真人实时开麦（官方弹幕游戏渠道要求）；数字人仅在 M5 可选试点且满足五条件（实名/真人实时驱动/AI 标识/原创形象/官方渠道） | 平台规则 |

## 1. 技术选型

- **形态**：Windows 桌面客户端（主播房间内运行，与行业主流一致；官方渠道要求主播真人开麦实时互动）。
- **栈**：Tauri 2（Rust）+ TypeScript + PixiJS（Canvas 渲染）+ SQLite（对账/看板数据）。
- **对接层**：Rust tokio 长连接（礼物/弹幕推送）；access_token 2 小时自动刷新；room_id 绑定；礼物置顶（≤6 个配置礼物）；任务启动；推送失败分页查询与重试。
- **引擎分层**（为 M4 换皮矩阵做准备）：触发层 / 规则层 / 物理效果层 / 主题层（皮肤+音效+话术包）。
- **CI**：GitHub Actions，双端测试零错误后才允许打包（沿用既有质量习惯）。
- **本地模拟模式**：无平台 API 也可完整跑一局（按钮模拟礼物/弹幕）——M1 验收不依赖平台账号。

- [ ] 通读《小玩法平台服务协议》《直播行为规范》，填完《合规自检清单》（本仓库 docs/compliance.md）
- [ ] 测试主播账号（本人或伙伴）+ 开播电脑（i5 + 独显 + 好麦）
- [ ] 一页纸产品设计文档：玩法循环、礼物映射表、禁用词库、视觉基调（docs/design-v1.md）
- **交付**：开放平台个人主体注册完成 + 设计文档 v1 冻结（软著移至 W3，代码就绪触发）

### M1 核心玩法 MVP（第 1-3 周）
- 引擎四分层骨架；打纸杯规则：一排 7 杯，单发击倒 1-3 杯（随机 + 礼物加权）
- 物理倾倒动画、命中大字、连击计数、高光慢放（0.5s）
- 局内循环：待机 → 开局（弹幕/礼物触发）→ 30-60s 打击回合 → 结算（总命中/最高连击/高光时刻）→ 待机
- 卡通音效 3 种（命中/连击/高光）；占位美术（几何卡通）先跑通
- **KPI（Day 21）**：本地模拟模式完整一局端到端，30fps+ 稳定，双端 tsc 零错误
- **软著触发（W3）**：M1 代码验收通过后，立即导出代码文档（≥60 页 / 3000 行）+ 设计文档，提交软著申请（建议加急）
- **Checkpoint**：Day 21 未达成 → 砍范围（7 杯→5 杯、去慢放），不延期

### M2 平台接入（第 3-5 周）
- access_token 2h 自动刷新、room 绑定、长连接推送（礼物/弹幕）、断线重连
- 礼物置顶 ≤6、任务启动、推送失败重试与对账（本地 SQLite 流水）
- 礼物映射落地：指定礼物 = 特殊弹效（多发/彩虹弹/慢放高光）；弹幕 = 免费击发（30s 冷却防刷）
- 合规硬编码：无回兑字段、术语库替换（赢输→命中/未中）、禁用词过滤器、金额展示只进不出
- **KPI（Day 35）**：测试主播房间真实礼物触发特效、弹幕免费参与生效、对账一致
- **Checkpoint**：Day 35 未达成 → M2 顺延 1 周，从 M3 借期

### M3 过审 + 公会 BD（第 5-8 周）
- 审核材料包：软著证明 + 合规设计说明 + 3 分钟演示视频 + 截图 + 话术对照表
- 驳回循环：记录原因 → 72h 内修复 → 重新提交
- **公会 BD（不等上线就开始）**：列 20 家团播公会 → 谈 10 家 → 签 3 家
  - 销售包：合规一页纸（"整治期唯一能安全挂载的解压玩法"）+ 演示视频 + 分成测算表（约 8% × 房间数）+ 定制主题报价单
- **KPI（Day 56）**：已提交审核；签约 3 家或 2 家 + 1 家在谈
- **Checkpoint（Day 60）**：未提交审核且无 2 家意向 → 触发降级决议（见 kill line）

### M4 主题矩阵 + 多平台（第 9-12 周）
- 主题 2：扎珠袋（换规则层 + 主题层，复用物理层）；主题 3：推砖头
- 多平台评估：视频号 + 微信小程序（用 ClinkLab 的微信全链路经验）/ B 站，选 1 个试水
- 公会数据看板：每房间命中数、礼物转化、主题 A/B（数据回流 = 留存护城河）
- **KPI（Day 90）**：2 个新主题上线 + 1 个新平台试水 + 累计 ≥20 房间挂载

### M5（可选，第 4-6 个月）
- 品牌定制首单（某品牌冠名定制杯/道具位）
- 数字人主播试点（仅当满足实名/真人驱动/AI 标识/原创形象/官方渠道五条件）
- 目标 100 房间挂载；授权模式试点（向小平台收一次性打包费）

## 4. 风险与对策

| 风险 | 概率 | 对策 |
|---|---|---|
| 软著周期卡上线 | 高 | W3 提交（代码就绪触发）+ 加急通道（约 1-3k）赶上 M3 审核窗口 |
| 审核驳回 | 中 | 合规自检清单 + 卡通资产 + 术语库；72h 修复循环 |
| 公会签不下来 | 中 | W5 提前启动 BD（不等上线）；拿"定制报价单"兜底 |
| 政策再收紧 | 中低 | 单向资金流是最大护盾；多平台期权 |
| 单人带宽不足 | 高 | AI 承担 ≥80% 编码；本人只做资质/BD/合规沟通/验收 |
| 平台自研替代 | 中 | 差异化 = 定制能力 + 合规套件 + 响应速度（平台自研不做长尾定制） |
| 同质化内卷 | 高 | 不卷单款机制，卷"出品速度 + 渠道 + 合规"（M4 矩阵） |

## 5. Kill line（写死）

- **Day 60**：未提交审核 且 公会意向 <2 家 → 决议会：降级为"纯分成副业"，停止渠道投入，主线回归 AI 交付。
- **Day 90**：未签约 3 家公会 且 挂载 <20 房间 → 游戏降副业（保留自然分成），不再追加时间；把主题引擎 + 合规套件打包为 B2B 定制产品卖（用 9 年展陈客户池）。
- 任何时点：若平台规则把"解压互动玩法"整类清退 → 立即止损转 M4 多平台方向，不恋战抖音单平台。

## 6. 任务分工（本人 vs AI）

**本人（不可替代）**：主体注册与软著、测试主播账号、公会 BD 与签约、审核沟通、每周 30min 验收、品牌单商务。
**AI（承担 ≥80% 编码）**：全部代码、CI、测试、占位美术、文档（设计/合规/销售包）、数据看板、主题换皮。
