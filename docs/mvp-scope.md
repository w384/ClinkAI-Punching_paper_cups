# 最小 MVP 盘点（2026-10-15）

> 目的：在继续写代码之前，先界定"最小能上线播起来"的边界，并找出**可能白写**的前提。

## 0. 一句话结论

代码已经跑到 **M1 临界点**（本地能完整跑一局）。
接下来最大价值不是继续写代码，而是 **1-2 天内确认 4 个前提**——其中一个（个人开发者能否发小玩法）若是否定答案，整个产品形态和 20 万路径都要变形。

## 1. 现状核实（今天已验证的事实）

| 项 | 状态 |
|---|---|
| 引擎四分层（trigger/rule/physics/theme） | ✅ 已实现 |
| 局循环（开始→45s→结算→重开） | ✅ 已实现 |
| 命中/连击/得分/高光 | ✅ 已实现 + 单测覆盖 |
| 本地模拟（弹幕 + 3 档礼物按钮） | ✅ 已实现 |
| 卡通音效（pong/boing/duang，合成） | ✅ 已实现 |
| `tsc --noEmit` 严格模式 | ✅ 0 错误 |
| 单元测试 | ✅ 15/15 通过 |
| 30fps 实机帧率 | ⚠️ 未验证（需起 dev server 人工看） |
| 平台接入 | ❌ 零 |
| 美术资产 | ⚠️ 仅代码几何占位 |
| 软著 | ❌ 未申请（待代码文档） |

## 2. MVP 判定标准（三条同时满足才算 MVP）

1. **能过审**：平台审核通过，拿到上线资格
2. **能真播**：主播在真实直播间开一场，礼物/弹幕能实时驱动画面，不掉线
3. **能连播**：一场直播 2 小时不用主播一直手点

> 不包含：赚钱。赚钱靠 M3 的公会签约，不是 MVP 的验收项。

## 3. 必须做（按工作流，工时为"一人 + AI"乐观值）

### A. 游戏本体收尾（3-4 天）

| # | 项 | 工时 | 为什么必须 |
|---|---|---|---|
| A1 | 结算画面（总命中/最高连击/高光次数 + 再来一局） | 0.5-1 天 | 观众仪式感；审核演示视频的重点画面 |
| A2 | 过审级卡通美术（杯/背景/命中特效/结算页，AI 生成统一风格） | 0.5-1 天 | **占位图是驳回高发点** |
| A3 | 自动循环连播（一局结束自动开下一局） | 0.5 天 | 主播不可能每 45 秒点一次 |
| A4 | 礼物映射外置配置（JSON，不改代码即可换礼物档位） | 0.5 天 | 不同主播/公会的礼物策略不同 |
| A5 | 打击感增强（震屏/杯子弹跳/粒子） | 0.5 天 | **P1，不阻塞过审，可后置** |

### B. 平台接入（5-7 天，最大不确定性）

| # | 项 | 说明 |
|---|---|---|
| B1 | 个人开发者入驻 + 小玩法应用创建 | 用户侧操作，含审核等待 |
| B2 | access_token 获取与 2h 自动刷新 | 官方开放平台鉴权 |
| B3 | room_id 获取与绑定（直播伴侣） | 绑定当前直播间 |
| B4 | 长连接接收礼物 / 弹幕（含心跳、断线重连） | 核心链路 |
| B5 | 礼物置顶配置（≤6 个） | 平台能力对接 |
| B6 | 任务启动接口 | 官方要求 |
| B7 | 推送失败 → 分页查询 + 重试 + SQLite 对账 | 丢事件 = 观众送礼没反应 = 事故 |

### C. 合规材料（2-3 天，不含软著等待期）

| # | 项 | 说明 |
|---|---|---|
| C1 | 软著：代码文档（≥60 页/3000 行）+ 设计文档 → 提交（建议加急） | 前置条件是代码就绪，现在已满足 |
| C2 | 演示视频（主播真人出镜开麦） | 官方明确要求 |
| C3 | 功能说明 + 玩法文档 + 界面截图 | 审核材料 |
| C4 | 话术合规 | ✅ 已内置 theme.words，无需额外工作 |

### D. 主播可用性（1-2 天，取决于接入形态）

| # | 项 | 说明 |
|---|---|---|
| D1 | 运行载体（网页 URL / exe） | **取决于 B 的接入形态**，见 §5 |
| D2 | 主播端控制条（开始/结束/静音） | MVP 只要开始+结束 |
| D3 | 主播话术脚本（照着念的引导词） | 既影响留存也影响合规 |

### 工时合计

A(3-4) + B(5-7) + C(2-3) + D(1-2) + 首播联调(2) ≈ **13-17 工作日**（约 3.5 周，不含资质与软著等待）
与 PLAN 的 W1-W5 基本吻合。

## 4. 明确砍掉（不进 MVP）

- 多平台（B站/虎牙/快手/视频号）
- 主题矩阵（换皮）
- 数字人主播（M5 才可选）
- 多房间被动收入
- 慢放高光、彩虹弹等高级特效
- 排行榜 / 榜单（合规风险高，且新规负面清单点名）
- 任何账号体系、积分、兑换

## 5. 四个未确认前提（先查，后写）

按影响从大到小：

| # | 未知数 | 若为否，后果 | 怎么确认 |
|---|---|---|---|
| 1 | **个人开发者能否发布小玩法** | 需转企业主体或找合作方，整个计划推迟 1-2 个月 | 开放平台入驻页 + 类目资质说明；或问已上线开发者 |
| 2 | **接入形态：网页 URL 还是客户端** | 决定要不要 Tauri 打包，省或费 2 天 | 小玩法接入文档 |
| 3 | **审核对美术完成度的容忍度** | 占位图被驳回 → 返工 3-5 天 | 看同类过审案例的截图水准 |
| 4 | **软著加急时效能否赶上审核** | 上线推迟 | 代理报价 + 历史时效 |

**这四条都是"查资料/问人"级别，成本半天到一天，但能避免 1-2 周的白写。**

## 6. 建议顺序（先查后写）

```
Day 1-2  确认 §5 的 1、2 两条 → 定下接入形态与主体路径
Day 2-4  按确认结果做 A（结算页 + 美术 + 连播 + 配置）
Day 4-6  提交软著（代码文档）→ 进等待期
Day 5-11 M2 平台接入（B2-B7），用测试直播间联调
Day 12-13 审核材料（C2-C3）+ 打包
Day 14-16 首播联调 → M1+M2 收官
```

## 7. MVP 验收清单（全部勾上才算"能播"）

- [ ] 真实直播间：观众发弹幕 → 2 秒内杯子倒下
- [ ] 观众送礼物 → 对应加量效果生效
- [ ] 断网 30 秒后恢复 → 事件不丢（对账生效）
- [ ] 一局结束自动开下一局，连续 2 小时无人工干预
- [ ] 结算页数据与后台统计一致
- [ ] 审核材料提报完成、软著证书到手
- [ ] 全流程 0 个禁用词、0 处回兑入口
